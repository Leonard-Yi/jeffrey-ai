# Pseudonymizer v2：自定义中文人名检测器

**日期**: 2026-06-05
**状态**: 设计中

## 1. 动机

当前 pseudonymizer 依赖 jieba 的 `nr` (person name) POS 标签来识别人名。但 jieba 是通用分词器，不是 NER 系统：

- 拆分多字名：`王磊` → `王/nr 磊/nr`（两个单字）
- 误标常见词：`星巴克` → `nr`
- 漏标名字：`张总` → `张/q 总/b`（完全不标 nr）

我们已经在 jieba 之上加了姓氏合并、老X fallback、title检测、非人名排除……但堆规则不能解决根本问题。

## 2. 设计目标

完全不用 jieba 的 `nr` 标签。保留 jieba 做三件事：分词（`jieba.cut`）、地名（`ns`）、机构名（`nt`）。人名检测由自定义 `NameDetector` 独立完成。

## 3. 架构

```
原文文本
  ↓
Stage 0: 预处理（归一化换行/tab，全角→半角映射）
  ↓
Stage 1: 候选生成（高召回）
  ├── 中文名：姓氏字典(500+) + 滑动窗口
  ├── 英文名：首字母大写序列检测
  ├── 前缀名：老/小/阿/大 + 单字模式
  ├── 后缀名：单字姓氏 + title（总/老师/教授…）
  ├── 重叠昵称：AA式（玲玲、欢欢）
  └── 引号昵称："铁军"、"胖子"
  ↓
Stage 2: 上下文评分（提精度）
  ├── 名字结构得分（姓+名合理性）
  ├── 前缀得分（老王小王阿强）
  ├── 后缀得分（总/老师/教授/工/经理/博士…）
  ├── 位置得分（主语/宾语位 vs 地点位）
  └── 排除扣分（已知非人名词，纯数字等）
  ↓
Stage 3: 过滤去重
  ├── 排除列表过滤
  ├── 相邻同类型实体合并
  ├── 重叠区间取高分
  └── 与 jieba ns/nt 实体合并输出
  ↓
实体列表 → pseudonymize
```

## 4. 中文名检测细则

### 4.1 姓氏字典

维护 ~500 个中文姓氏（含复姓：欧阳、司马、上官、诸葛、令狐、慕容等）。扫描原文每个字符位置，命中姓氏 → 触发候选生成。

### 4.2 名字用字频率表

统计常见中文名字用字及其频率。用于 Stage 2 评分：候选名的每个字在频率表中的排位 → 名字结构得分。

排除：虚词（的、了、在、是）、动词（做、搞、弄、给、让）、数字（超过名字常用范围）。

### 4.3 前缀模式

| 前缀 | 示例 | 检测规则 |
|---|---|---|
| 老 | 老王、老周 | `老` + 姓氏字典命中 |
| 小 | 小王、小张 | `小` + 姓氏字典命中 |
| 阿 | 阿强、阿玲 | `阿` + 常见名字用字/昵称用字 |
| 大 | 大刘 | `大` + 姓氏字典命中 |

### 4.4 后缀/Title 模式

Title 列表（30+）：
`总、老师、教授、工、经理、主任、博士、先生、女士、小姐、同志、局长、处长、科长、部长、校长、院长、律师、医生、会计、工程师、设计师、编辑、导演、老板、师傅`

检测规则：左右相邻的单字 + 在姓氏字典中 → 合并为 `姓+Title` 实体。

### 4.5 重叠昵称

`玲玲、欢欢、豆豆、婷婷、伟伟`

规则：AA 式 2 字重叠 + 首字在昵称用字表中 → 人名候选。昵称用字表从常见名字用字表中筛选高频重叠字。

### 4.6 引号昵称

`人称"铁军"的王磊` → `铁军` 是昵称
`大家都叫他"胖子"` → `胖子` 是昵称

规则：中文引号（`""`）或半角引号（`""`）内 1-4 个中文字 → 人名候选。

### 4.7 双关词处理

`黎明、高峰、杨柳、陈述、方向` → 这些词可以是人名也可以是普通词。

规则：必须有明确的人称语境（前缀/后缀/主语位/宾语位）才判定为人名。单次出现且无上下文 → 不伪名化，保留给 LLM 处理。

## 5. 英文名检测细则

### 5.1 检测模式

| 模式 | 示例 | 正则 |
|---|---|---|
| 单个英文词（首字母大写） | John, Michael | `[A-Z][a-z]+` |
| 名+姓（空格分隔） | Michael Chen | 两个连续大写词 |
| 缩写名 | J.P. Morgan | `[A-Z]\.` |
| 连字符名 | Sarah-Jane | `[A-Z][a-z]+-[A-Z][a-z]+` |
| 撇号名 | O'Brien | `[A-Z][a-z]+'[A-Z][a-z]+` |
| 头衔前缀 | Dr. Smith, Mr. Lee | `Dr\.\|Mr\.\|Ms\.\|Mrs\.\|Prof\.` |

### 5.2 排除规则

| 应排除 | 原因 | 规则 |
|---|---|---|
| AI, CEO, API, RAG | 技术术语/缩写 | 全大写 |
| john@gmail.com | 邮箱 | 含@符号 |
| React, Python, Java | 编程语言 | 已知列表 |
| the, a, an, is | 英文功能词 | 停用词列表 |

### 5.3 内部空格处理

`Michael Chen` → 空格是名+姓分隔，保留为单实体 `"Michael Chen"`
`John, Mary` → 逗号是两个人分隔，拆为 `"John"` + `"Mary"`

区分方式：两个大写词之间仅隔空格 → 合并。中间有标点 → 分割。

## 6. 分离器细则

### 6.1 字符归一化

预处理阶段：

| 输入 | 归一化为 |
|---|---|
| `\n` `\r` `\t` | 空格 |
| 全角空格 `　` (U+3000) | 半角空格 |
| 全角逗号 `，` | 半角逗号 `,` |
| 全角句号 `。` | 半角句号 `.` |
| 全角分号 `；` | 半角分号 `;` |

### 6.2 名字分隔符

```
句子边界（跨句号不会是同一人名）：。 . ！ ! ？ ?
硬分隔（明确的人名边界）：， , ； ; 、
软分隔（可能是也可能不是边界）：空格 换行
```

硬分隔符 → 强制拆分为独立候选名。
软分隔符 → 看两侧内容：如果一侧是中文姓氏+另一侧是中文姓氏 → 是边界。如果两侧是英文大写词+英文大写词 → 不是边界（Michael Chen 保留空格）。

### 6.3 点号特殊处理

`J.P.` → 两侧大写字母 → 名字内部，不分割
`王磊.今天` → 句号 → 句子边界
`www.google.com` → URL → 不纳入名字检测

### 6.4 括号、引号、特殊符号

| 符号 | 处理 |
|---|---|
| `()` `（）` | 括号内容不纳入名字（如 `王磊(微信:xxx)` → 只取 `王磊`） |
| `@` | @前缀剥离（如 `@王磊` → 取 `王磊`） |
| `#` `￥` `$` | 非法名字字符，作为边界 |
| 连续8位以上数字 | 电话号码，作为边界且不纳入名字 |

## 7. 排除列表

### 7.1 已知非人名词

`星巴克、麦当劳、肯德基、区块链、人工智能、机器学习、深度学习、神经网络、互联网、物联网、大数据、云计算`

维护在独立的 constant 文件中，方便扩展。

### 7.2 动态排除

如果原文中出现了"在XX"（位置模式）、"XX公司"、"XX集团"等上下文 → 即使 XX 碰巧像人名，也降级为"不伪名化"。这些是 LLM 的上下文信息，不应替换。

## 8. 日韩名字

现阶段不做特殊处理。日语名（田中太郎）、韩语名（金秀贤）如果被中文姓氏字典命中，按中文名处理。不被命中的情况 → 不做伪名化，由 LLM 处理。

## 9. 与现有系统的集成

- `src/lib/pseudonymizer.ts` 的 `extractEntities()` → 替换为 `NameDetector.detect(text)`
- `src/lib/nameDetector.ts` → 新文件，独立模块
- jieba 的 `ns`/`nt` 检测保留不动
- `src/app/api/persons/resolve/route.ts` 的 `extractNames()` → 同样使用 `NameDetector`

## 10. 测试计划

至少 30 个测试用例，覆盖：

1. 基础中文名（2-4 字）
2. 复姓
3. 前缀名（老/小/阿/大）
4. 后缀 title（10+ 种）
5. 英文名（单名、全名、缩写、连字符、撇号）
6. 多个人名（顿号/逗号/空格/和/跟/与分隔）
7. 换行/tab在名字中
8. 全角/半角标点混合
9. 双关词（黎明/高峰）
10. 重叠昵称（玲玲/欢欢）
11. 引号昵称
12. 括号/@/电话号码干扰
13. 已知非人名词排除
14. 模糊指代（某人/一个XX的人）→ 不应伪名化
15. 全大写缩写 → 不应伪名化
